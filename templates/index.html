¿Cómo se aplicó cada modelo?

Esta sección muestra qué datos recibe cada modelo, qué proceso realiza, qué resultado produce y por qué se utilizó en el caso de CONAUTI.

1. Árbol de Decisión

Supervisado · Scikit-learn · Clasificación
Entrada: las 8 variables de cada interacción: longitud de solicitud, tiempo de respuesta, herramientas, intentos, tokens, errores, reintentos API y uso de CPU.
Cómo funciona: aprende reglas a partir de ejemplos con etiqueta Anomalia (0 normal / 1 anómala) y divide los datos mediante condiciones hasta decidir la clase.
Aplicación: se entrena con los datos de entrenamiento y después clasifica las interacciones del conjunto de prueba.
¿Para qué se aplicó? Para tener un modelo supervisado, interpretable y fácil de explicar que permita decidir si una interacción es normal o anómala.

2. K-Means

No supervisado · Scikit-learn · Agrupamiento
Entrada: las 8 variables estandarizadas de las 250 interacciones, sin usar la etiqueta de anomalía.
Cómo funciona: busca puntos similares y los organiza alrededor de centros llamados centroides. En este proyecto se configuraron 4 grupos.
Aplicación: cada interacción recibe una etiqueta de grupo y el resultado se guarda como Grupo_KMeans.
¿Para qué se aplicó? Para descubrir perfiles de comportamiento entre las interacciones y observar si existen patrones diferenciados sin depender de una etiqueta previa.
{% if kmeans %}
Resultado: {{ kmeans.get('grupos','—') }} grupos encontrados.
{% endif %}

3. DBSCAN

No supervisado · Scikit-learn · Agrupamiento por densidad
Entrada: las mismas 8 variables estandarizadas utilizadas para analizar la similitud entre interacciones.
Cómo funciona: busca zonas donde existen suficientes puntos cercanos. Los puntos que no pertenecen a una zona suficientemente densa se marcan como ruido (-1).
Aplicación: se ejecuta sobre todas las interacciones y se guardan el grupo y los casos considerados ruido como Grupo_DBSCAN.
¿Para qué se aplicó? Para detectar comportamientos aislados que podrían ser útiles como señales de posibles anomalías, complementando el análisis de K-Means.
{% if dbscan %}
Resultado: {{ dbscan.get('grupos','—') }} grupos y {{ dbscan.get('ruido','—') }} registros marcados como ruido.
{% endif %}

4. MLP

Deep Learning · TensorFlow/Keras · Clasificación binaria
Entrada: las 8 variables estandarizadas de una interacción.
Cómo funciona: una red con capas Dense de 32 y 16 neuronas aprende relaciones entre las variables. La salida Sigmoid genera una probabilidad de anomalía.
Aplicación: se entrena con ejemplos etiquetados. Si la probabilidad obtenida es ≥ 0.5, se clasifica como anomalía.
¿Para qué se aplicó? Para comparar una red neuronal con el Árbol de Decisión y disponer de un clasificador capaz de aprender relaciones no lineales entre las variables.

5. Autoencoder

Deep Learning · TensorFlow/Keras · Detección de anomalías
Entrada: las 8 variables estandarizadas, pero el entrenamiento utiliza únicamente las interacciones normales.
Cómo funciona: aprende a reconstruir el comportamiento normal. Después calcula el error entre los valores originales y reconstruidos.
Aplicación: se establece un umbral con el percentil 95 del error de reconstrucción de los datos normales. Si una interacción supera ese umbral, se marca como anómala.
¿Para qué se aplicó? Para detectar comportamientos que se alejan del patrón normal sin necesitar entrenar directamente con ejemplos de anomalías.
{% if autoencoder %}
Resultado: umbral {{ '%.4f'|format(autoencoder.get('threshold',0)) }} · {{ autoencoder.get('anomalias_detectadas','—') }} anomalías detectadas.
{% endif %}

6. CNN

Visión Computacional · TensorFlow/Keras · Clasificación
Entrada: las 8 variables estandarizadas se transforman en una representación matricial de 16×16 píxeles para poder utilizar una CNN.
Cómo funciona: las capas convolucionales extraen patrones de la representación 16×16; luego las capas finales clasifican la interacción como normal o anómala.
Aplicación: se generan imágenes sintéticas a partir de las variables, se entrena la CNN con las etiquetas 0/1 y se obtiene una probabilidad de anomalía.
¿Para qué se aplicó? Para incorporar el enfoque de visión computacional solicitado en la pauta y comprobar cómo una CNN puede trabajar sobre una representación visual de los datos de interacción.
